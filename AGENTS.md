# AGENTS.md — правила розробки Кодика

## Призначення

Кодик — навчальне середовище Python для школярів. Основний продукт — статичний сайт на GitHub Pages: https://kosachevlad.github.io/python/ . Репозиторій: https://github.com/kosachevlad/python .

Спілкуйся з користувачем українською. Тексти інтерфейсу роби зрозумілими дітям і вчителям. Зберігай наявне перемикання UA / EN; нові функції узгоджуй із мовою інтерфейсу, де це передбачено відповідним модулем.

Цей файл описує робочі правила та важливі особливості проєкту. Актуальну версію й реалізацію завжди перевіряй у коді. Прямі інструкції користувача мають пріоритет над рекомендаціями цього файлу.

**Поточний обсяг розробки — тільки вебзастосунок.** Не оновлюй Android-оболонку, APK або Android-сумісність без нового прямого запиту користувача.

## Перед змінами

1. Перевір поточну гілку, стан робочої копії, актуальний main та наявність вкладених AGENTS.md.
2. Прочитай index.html: саме він визначає активні CSS/JS і порядок завантаження.
3. Перевір відповідні розділи MOBILE.md, MINI-IDE.md, TURTLE.md, TKINTER.md або ROBOT.md.
4. Змінюй лише те, що потрібно для задачі. Не перезаписуй сторонні чи незакомічені зміни.
5. Не вважай дозвіл на одну операцію універсальним дозволом на видалення даних, надсилання повідомлень чи публікацію будь-якого майбутнього результату. Враховуй обсяг поточного запиту та вже надані користувачем дозволи.

Для GitHub API оновлюй ref із перевіркою очікуваного попереднього SHA. У звичайному Git не застосовуй force push без окремої обґрунтованої потреби та дозволу.

Основний скрипт має історичні обгортки та глобальні змінні classic scripts. Перед зміною run, executeCode, renderAll та обробників кнопок перевір усі їх перевизначення. Порядок scripts важливий: mobile-workspace.js обгортає функції після project-ide.js, feedback.js використовує вже створений footer.

Нову ізольовану функціональність за можливості винось в окремий зрозумілий модуль. Не додавай нескінченні таймери для виправлення DOM, якщо можна використати явний виклик або подію. Старі regex/таймери, які вгадували рядок помилки, видалені. Не повертай їх: використовуй структуровані дані Python та явні виклики оновлення.

## Поведінка, яку потрібно зберігати

- На телефоні постійно доступні «Код», «Результат», «Запустити». Після запуску показується результат; для input() поле відповіді видиме й отримує фокус. Перевіряй також кілька запитів поспіль.
- На широкому екрані редактор і результат залишаються поруч.
- Кнопка «Поділитися кодом і результатом» розміщена внизу сторінки, поза приховуваною бічною панеллю. Вона доступна в обох мобільних режимах.
- Кнопка «Зворотний зв’язок» розміщена нижче поширення. Не змінюй адресу отримувача без запиту.
- Не повертай напис «Python готовий»: після успішної підготовки індикатор прихований. Під час завантаження та помилки користувач має бачити стан і можливість повторити.
- Підсвітка токенізує вихідний код один раз. Не застосовуй нові regex-заміни до вже створеного HTML: це раніше пошкоджувало коментарі.
- Undo/redo ізольовані між файлами. Закриття вкладки не видаляє файл і не переносить його код у сусідню вкладку.
- Не очищуй localStorage, проєкти або резервні копії під час оновлення без необхідності. Для зміни формату збереження потрібна міграція зі збереженням даних.

## Python, кеш та запуск

Використовуй window.ensureKodikPython() із python-engine.js в обох режимах. Не створюй другий незалежний завантажувач: одночасні фоновий і ручний запуски мають використовувати спільний Promise.

Поточне середовище — Pyodide 0.26.2. Перший запуск потребує завантаження та ініціалізації WASM. Не обіцяй миттєвий або гарантовано автономний перший запуск. Поважай режим економії трафіку.

Основні ресурси Python кешуються окремо від версії інтерфейсу. Не видаляй цей кеш через звичайне оновлення сайту. При зміні версії Pyodide узгодь URL, назву кешу, список ресурсів і тестову підготовку.

Наявний inputPattern збирає буквальні input() через regex. Це не повна реалізація довільного інтерактивного вводу. Довільний Python виконується на головному потоці; не заявляй про надійне примусове переривання без відповідного механізму.

## Міні-IDE і файли

Проєкт віртуальний: імпорт/експорт файлів і .kodik.json, а не прямий доступ до папки користувача.

Зберігай ізоляцію навчального режиму й Міні-IDE, перевірку відносних шляхів, UTF-8/base64, резервні копії та синхронізацію Python → дерево файлів. Під час очищення файлової системи не слідуй symlink і не виходь за каталог проєкту.

Запис із Python не повинен мовчки знищувати новіші зміни редактора. Зберігай механізм конфліктних копій. Перевіряй повторні запуски, очищення кешу імпортованих модулів та відновлення cwd.

## Графічні бібліотеки

Це навчальні порти, а не повні настільні бібліотеки. У документації та відповідях чітко називай фактично підтримувані можливості.

- turtle: зберігай анімовану чергу, скидання стану між запусками та коректне завершення. Перевіряй базовий квадрат, колір і повторний запуск.
- tkinter: зберігай живі callbacks після mainloop(), вивід помилок у термінал і синхронізацію файлових записів. Скидання має скасувати таймери й звільнити PyProxy.
- Зміни фокусу, keysym та координат SVG перевіряй на examples/cat-maze.py: він компенсує масштаб у власному коді. Не допускай подвійного масштабування.
- robot: pickUp() збирає кристал ПЕРЕД роботом. Python обчислює стани, а панель відтворює запис; її «Стоп» не перериває довільний Python. Зберігай CollisionError/OutOfBoundsError, обмеження запису та сумісність карт.
- При використанні оригінального коду/ресурсів зберігай сторонні ліцензії, зокрема licenses/robot-python.txt.
- Розширення сумісності tkinter перевіряй на конкретному прикладі. Не підміняй відсутню функцію мовчазною заглушкою, яка приховує помилку.

## Поширення PNG і зворотний зв’язок

Ширина PNG визначається видимим кодом, результатом і заголовками з відступами. Не повертай фіксовану ширину 1000 px. Кінцеві пробіли не мають розтягувати зображення; довгі рядки не обрізаються. Зберігай підсвітку та українські символи.

Якщо Web Share API відмовив, показуй зрозуміле повідомлення, технічний код помилки й можливість завантажити готовий PNG. Скасування користувачем відрізняй від помилки генерації. Не стверджуй, що файл гарантовано збережений, лише тому, що почався запит на завантаження.

Форма зворотного зв’язку використовує mailto: і відкриває підготовлений лист. Надсилає його сам користувач. Не додавай автоматично код, файли, токени чи інші дані користувача до повідомлення.

## Діагностика Python

Прочитай ERRORS.md. Використовуй compiler/traceback для позицій та Pyflakes для вибраних статичних попереджень. Не вгадуй номер рядка через regex повідомлення. Враховуй файл, Unicode-стовпці та вихідний код до підстановки input(). Попередження не блокують запуск; синтаксичні помилки блокують його до запиту input(). Перевірка коду не повинна виконувати програму. Зберігай початковий код живих callback окремо від поточного тексту редактора та не переходь до застарілої позиції. Не видаляй ліцензію Pyflakes.

## Перевірки

Запускай перевірки, які відповідають зміні. Для правок лише документації достатньо перевірити точність шляхів і команд; не потрібно перебудовувати застосунок або APK.

Швидкі цільові перевірки з кореня репозиторію:

~~~sh
node highlight.test.cjs
node share-image.test.cjs
node share-errors.test.cjs
node feedback.test.cjs
node project-store.test.cjs
~~~

Для змін інтерфейсу, запуску, вводу, проєктів або кешування перевіряй реальний браузер і Python:

~~~sh
node tests/prepare-browser.cjs
npm install --no-save --package-lock=false playwright@1.51.1
npx playwright install --with-deps chromium
node tests/mobile-browser.cjs
~~~

python-diagnostics.test.cjs, project-runtime.test.cjs, turtle-node.test.cjs, tkinter-node.test.cjs та robot-node.test.cjs потребують PYODIDE_DIR з локальними файлами Pyodide. tests/prepare-browser.cjs готує їх у .browser-test/pyodide. Приклад у PowerShell:

~~~powershell
$env:PYODIDE_DIR = (Resolve-Path .browser-test/pyodide).Path
node project-runtime.test.cjs
~~~

У shell Linux/macOS:

~~~sh
PYODIDE_DIR="$PWD/.browser-test/pyodide" node project-runtime.test.cjs
~~~

tests/prepare-browser.cjs потребує мережі для завантаження ресурсів. Нові JS із index.html копіюються автоматично; нові CSS та допоміжні ресурси додай до списку копіювання.

Браузерні сценарії перевіряй на 320–390 px і desktop: фокус input, перемикання режимів, видимість footer, діалоги, повторний запуск. Зміни графіки перевіряй також візуально.

Для download-тесту явно задавай сценарій підтримки navigator.share та timeout очікування. Не залишай необмеженого очікування системного меню поширення.

Workflow .github/workflows/test-mobile.yml має фільтр гілки features/mobile-ux та workflow_dispatch. Пуш в іншу гілку сам по собі не означає, що ці тести запустилися. Перевір фактичний результат CI.

## Версія та публікація

Для користувацьких змін узгоджуй видиму версію, посилання з query version у index.html та версію кешу сайту в sw.js. Перевір наявні рядки версії в активних модулях; не перейменовуй історичні файли без потреби.

Зміни лише AGENTS.md або іншої документації не потребують нової версії інтерфейсу.

Публікуй у межах дозволеного користувачем обсягу. Після оновлення main перевір GitHub Pages deployment. Не повідомляй, що сайт уже оновлений, якщо deployment ще триває або завершився помилкою.

У підсумку коротко напиши: що змінено, як перевірено, яка версія доступна та які суттєві обмеження залишилися. Не видавай емуляцію браузера за тест на фізичному телефоні.

## Android — історична реалізація, поза поточним обсягом

Цей розділ довідковий. Наступні вказівки застосовуються тільки після нового прямого запиту на Android-розробку.


Android-оболонка розробляється в окремій гілці android/apk-android9. Перевір її актуальний стан перед роботою: вебоновлення main не потрапляють в уже зібраний APK автоматично.

Мінімальна підтримка — Android 9 (API 28). Зберігай безпечний WebViewAssetLoader, ізоляцію локальних ресурсів, native share і роботу імпорту/експорту.

Перед збіркою перевір android/prepare-web.cjs: він має копіювати всі актуальні модулі та ресурси й коректно підключати локальний Pyodide. Узгоджуй web version, versionCode, versionName та назву APK.

Перевір збірку, lint, мінімальний SDK і підпис. Для тестових APK з різними підписами попереджай про експорт проєктів перед можливим видаленням старого застосунку. Не обіцяй сумісність, яку не перевірено на пристрої.
