# Firebase: спільні лайки у «Роботах учнів»

Ця інтеграція працює на GitHub Pages без власного сервера. Кожна робота має спільний лічильник голосів. Кожен анонімний Firebase користувач може створити **один незмінний голос на роботу**. Інші відвідувачі бачать суму голосів після відкриття/повторного відкриття галереї; це не постійний realtime-стрим.

## Підключення (власник Firebase-проєкту)

1. Відкрий https://console.firebase.google.com/ і створи Firebase-проєкт (або обери власний).
2. У **Project settings → Your apps** зареєструй вебзастосунок, наприклад `kodik`, та скопіюй `firebaseConfig`.
3. Заповни **тільки публічні вебполя** файлу `firebase-config.json`: `apiKey`, `authDomain`, `projectId`, `appId`. За потреби додай `storageBucket`, `messagingSenderId` тощо. **Не вставляй service account JSON, private keys або інші секрети**. Web API key не є серверним секретом.
4. У **Authentication → Sign-in method** увімкни **Anonymous**. Перевір, що домен `kosachevlad.github.io` дозволений у **Authentication → Settings → Authorized domains** (якщо цього вимагає твоя конфігурація).
5. Створи **Cloud Firestore** (Standard edition, зазвичай Spark/free tier достатньо для невеликої галереї). У **Firestore Database → Rules** встанови правила з `firestore.rules` і натисни **Publish**. **Якщо у цьому самому Firebase-проєкті є інші колекції, об'єднай правила, а не замінюй їх усі**.
6. Злий PR з кодом та конфігурацією в `main`; онови сайт. Перевір лайк у двох різних браузерах: загальна кількість збільшується, повторне голосування в тому самому браузері заблоковане.

## Структура Firestore

`studentWorks/{workId}/votes/{anonymousUid}` → `{ createdAt: serverTimestamp() }`

Число лайків отримуємо через Firestore `getCountFromServer` для колекції голосів. Правила дозволяють публічний підрахунок, але створювати можна лише документ із власним UID, один раз. Оновлювати або видаляти голоси клієнту заборонено.

## Зауваження

- До налаштування Firebase відвідувачі бачать стан «Лайки недоступні» замість неправильного 0.
- Старі лайки з `localStorage` **не переносяться автоматично**, бо раніше не існувало спільного сховища. Нова статистика починається з нуля.
- Анонімна авторизація обмежує повторне голосування в межах збереженого акаунта браузера. Видалення даних браузера, інкогніто або інший пристрій можуть створити новий UID. Це **не захист від накрутки**; для сильнішого захисту потрібні App Check, ліміти та серверна логіка.
- Публічний доступ `list` дозволяє Firestore-агрегацію та технічно також дає змогу прочитати псевдонімні UID голосів (без ПІБ чи email). Для повністю приватних голосів потрібен серверний підрахунок.
- Число оновлюється при відкритті галереї та після поставленого лайка; агрегатні запити не підтримують realtime-слухачів.
- Вартість і квоти Firestore залежать від кількості відкриттів галереї й голосів. Перевір квоти та встанови budget alerts.
- Код не перевірено інтеграційно до створення власного Firebase-проєкту.
